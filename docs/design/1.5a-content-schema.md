# 1.5a — Content schema: file layout and type map

WP-1.5a adds a RamRPG content loader **over** RamCore's content pipeline
(`dev.willram.ramcore.content.{ContentLoader, SpecLoader, ContentDeserializer, ContentDefinition,
ContentLoadResult, SpecLoadResult, SourceRef}`). RamRPG never re-implements HOCON parsing, `extends:`
inheritance, duplicate/cycle detection, or error aggregation — those are RamCore's. RamRPG owns only
the mapping from a merged node to a **pure** RPG spec (one deserializer per type) plus one policy
RamCore leaves open (unknown directory = error). This is gated on **G8** (build on RamCore **2.0.1**,
the un-relocated API, so RamCore's Configurate loader works at runtime).

## File layout and directory → type map

Content lives under `plugins/RamRPG/content/`. Each **subdirectory name is the content type**; each
`.conf` (also `.yml`/`.yaml`) file holds one entry (a map with an `id`) or a top-level list of entries.

| Directory | Spec (`core/config/specs/`) | Domain type built by the registrar |
| --- | --- | --- |
| `stats/`    | `StatSpec`          | `api.stats.StatDefinition` |
| `items/`    | `ItemSpec`          | `api.items.ItemDefinition` |
| `skills/`   | `SkillSpec`         | `api.skills.SkillDefinition` |
| `enchants/` | `EnchantSpec`       | `api.enchants.RPGEnchantment` |
| `entities/` | `EntityProfileSpec` | `api.entities.EntityProfile` |
| `reforges/` | `ReforgeSpec`       | `api.reforges.ReforgeDefinition` |
| `gems/`     | `GemSpec`           | `api.sockets.GemDefinition` |

`RpgContentLoader.load(Path): RpgContentLoadResult`. `RpgContentLoadResult` exposes the typed lists
(`items`, `stats`, …), a flat `definitions(): List<RpgContentSpec>`, and `errors(): List<ValidationError>`.
`ContentRegistrarRpg.registerAll(result, owner)` registers every spec into the live registries and
returns any registration-time errors. `extends:` deep-merge (child scalar wins, child list replaces,
maps merge) comes **free** from RamCore's `ContentLoader` — RamRPG does not implement inheritance.

### HOCON quoting rule (important)

`:` is a HOCON key/value separator, so **every namespaced id or map key must be quoted**:
`id = "ramrpg:test_sword"`, `base-stats { "ramrpg:damage" = 50.0 }`. Field keys with dashes
(`base-stats`, `custom-model-data`, `per-level`) need no quoting.

## HOCON shape of each spec

Common to all: `id` (required, `ns:value`), `extends` (optional parent id), `name` (MiniMessage →
`Component`, defaults to the id value). Full per-field shape and defaults are the KDoc header of each
`core/config/specs/*.kt`. Summary:

- **StatSpec** — `symbol`, `color` (named or `#rrggbb`), `base` (defaultBase), `per-level`, `min`,
  `max`, `format` (`WHOLE`|`ONE_DECIMAL`|`PERCENT`), `translation-key`.
- **ItemSpec** — `material` (raw String), `rarity`, `categories` (`ItemCategory` list), `base-stats`
  (statId → ADD amount), `description` (MiniMessage list), `stat-rolls` (`{stat,min,max}` list),
  `max-stack`, `custom-model-data`, `allow-vanilla-wrapper`.
- **SkillSpec** — `description`, `max-level`, `bar-color` (Adventure `BossBar.Color`),
  `xp-curve {type=polynomial|linear, base, mul}`, `rewards` (`stat_per_level` / `unlock_ability`).
- **EnchantSpec** — `max-level`, `targets` (`ItemCategory` list), `rarity` (`EnchantmentRarity`),
  `description`, `conflicts-with` (enchant id list).
- **EntityProfileSpec** — `base-stats`, `xp-source`, `xp-amount`, `skill`, `is-boss`, `display-name`.
- **ReforgeSpec** — `universal` (statId → amount), `by-category { CATEGORY { statId = amount } }`.
- **GemSpec** — `stats` (statId → amount).

### Purity (no Bukkit in specs)

Every `core/config/specs/*.kt` is Bukkit-free so it unit-tests off-server. The only Bukkit-bound field
an item carries is its `org.bukkit.Material`; `ItemSpec` therefore holds `material` as a raw String and
`ContentRegistrarRpg` (which *may* touch Bukkit) resolves it with `Material.valueOf` on the server. A
bad material becomes an aggregated `ValidationError` from `registerAll`, not a thrown exception.

## Errors and SourceRef aggregation

The loader **never throws**; it returns a result whose `errors()` is the concatenation of:

1. **Parse / inheritance errors** from RamCore's `ContentLoader` — malformed HOCON, missing `id`,
   invalid `id`, missing `extends` parent, inheritance cycles, duplicate ids. Each already carries its
   `SourceRef` (file + path; path is a list index like `[2]` for list entries, else empty).
2. **Deserialize errors** from RamCore's `SpecLoader` — a `ContentDeserializer` throwing
   `ContentDeserializeException` (unknown enum value, missing required field, bad `stat-roll` range).
   `SpecLoader` tags each with `ValidationError.at(file, path, message)`; for a single-entry file it
   substitutes the entry id for the empty path, so the error reads `[file] id: message`.
3. **Unknown-type errors** added by RamRPG. RamCore's `SpecLoader` intentionally *ignores* a directory
   with no registered deserializer (so a project can load only the types it wants); RamRPG instead
   treats an unrecognised directory as authoring error and emits one `ValidationError` per entry that
   **names the directory** and carries its file + id.

Three broken files therefore yield three errors — see `ContentLoaderErrorAggregationTest`,
`ContentLoaderUnknownTypeTest`.

## Off-thread load contract (Folia-safe)

RamCore's loader does **blocking file I/O** and is not Folia-thread-sensitive. `ContentModule`
therefore: (1) resolves the seven registries + `PlatformScheduler` from its `ServiceContext`;
(2) runs `RpgContentLoader.load` on `PlatformScheduler.runAsync`; (3) applies `ContentRegistrarRpg`
registrations back on `runGlobal`, where the RPG registries expect their mutations; (4) logs the
aggregated errors. All wiring is in `ContentModule` — nothing is added to `RamRPG.kt` (B5). The pure
`RpgContentLoader`/spec types carry no scheduler dependency, so the four tests run off-server.

## Seams left open

- **Effects (WP-1.5b).** Items/enchants will carry an `Effect` bundle. 1.5a deliberately does **not**
  model the effect schema or build an `EffectActionRegistry`: `EnchantSpec`'s enchantment returns
  `emptyList()` effects, and `ItemSpec` leaves the `effects` key unread. Adding effect parsing later is
  purely additive.
- **Loot tables.** `EntityProfileSpec.toProfile()` sets `lootTable = null`; making loot tables editable
  content (a `loot/` type resolved by id reference) is out of 1.5a scope. HOCON profiles inherit no
  drops until then; the code `builtin` path keeps its table.
- **Stat owner scoping.** `StatService.registerDefinition` takes no owner, so HOCON stat definitions
  cannot be unregistered by owner (matches the existing `StatService` contract). All other types
  register under owner `ramrpg-content` and are cleanly unregisterable for `/rpg reload` (WP-1.5c).

## Deprecation

`core/config/ContentOverrides.kt` (`ContentOverrideLoader`, the JSON-patch path that can only *tweak*
existing builtins) is now `@Deprecated` and kept working for one release. It shares the `content/`
directory with the new loader harmlessly: `RpgContentLoader` reads only `.conf`/`.yml`/`.yaml`, the
shim reads only `.json`.

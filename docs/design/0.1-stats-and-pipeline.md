# 0.1 — Stats and the damage pipeline

Baseline of what the code implements today (`builtin/identity/Builtins.kt`, `builtin/stats/BuiltinStats.kt`,
`api/combat/Combat.kt`, `builtin/stats/DamageStages.kt`). Every later WP reads this before adding a stat
or a pipeline stage.

## Stat registry (14 today)

{`WHOLE`, `ONE_DECIMAL`, `PERCENT`}. Registered in `BuiltinStats.registerAll`.

**Landed in WP-2.3a:** one `resistance_<type>` stat per damage type (physical, fire, frost, lightning,
arcane, poison, true) — seven more, registered in `BuiltinStats`. Sets/perks/buffs contribute through
`StatProvider`s, never new stat keys. The projected end-state is ~21–26 stats; treat "26" in the
roadmap as an aspiration, not a current count.

## Stat aggregation order

`StatService` aggregates modifiers as **ADD → MULTIPLY_BASE → MULTIPLY_TOTAL** (`StatServiceTest`).
Providers register under an owner and are re-queried on the dirty triggers (equipment change, world
change, reload).

## Damage pipeline

`DamageContext(attacker, victim, cause, weapon, baseDamage)` carries `finalDamage`, `tags`
(`DamageTag` ∈ CRIT/TRUE/MAGIC/MELEE/RANGED/SECONDARY/INDIRECT), `components: Map<DamageTypeKey,Double>`,
`metadata`, and a `secondaryQueue`. Stages run by ascending `priority` (`DamagePriority`). The pipeline
re-runs up to 8 ferocity chains; a stage that seeds `components` must be paired with exactly one that
consumes them, reset per chain.

| Priority | Const | Stage today | Formula |
| --- | --- | --- | --- |
| 100 | `WEAPON_BASE` | WeaponBaseStage | `finalDamage = damage` if damage > 0 |
| 200 | `STRENGTH` | StrengthStage | `×(1 + strength/100)` |
| 300 | `ENCHANT_OFFENSE` | EnchantDamageStage | enchant offensive contributions |
| 400 | `EFFECT_OFFENSE` | *(empty)* | reserved for TriggeredEffect/DamagePipelineEffect offense |
| 500 | `CRIT_ROLL` | CritRollStage | roll < crit_chance ⇒ `×(1 + crit_damage/100)`, tag CRIT |
| 600 | `ELEMENTAL_BREAKDOWN` | ElementalBreakdownStage | **WP-2.3a**: seeds `components` by type (default all-physical, all-true if TRUE) |
| 700 | `ABILITY_MOD` | *(empty)* | reserved for ability damage modifiers |
| 1000 | `RESISTANCES` | ResistancesStage | **WP-2.3a**: reduces each component by `resistance_<type>` via `×(1 − r/(r+100))`; skips `true` |
| 1100 | `ARMOR_MITIGATION` | ArmorMitigationStage | `×(1 − def/(def+100))`, skipped if TRUE |
| 1200 | `TRUE_DEFENSE` | TrueDefenseStage | fire/lava causes: `×(1 − td/(td+100))` |
| 1300 | `ENCHANT_DEFENSE` | EnchantDamageStage | enchant defensive contributions |
| 1400 | `SHIELDS` | *(empty)* | **WP-6.1b**: Shielded affix as DamagePipelineEffect |
| 1500 | `THORNS` | *(empty)* | **WP-6.1b**: Thorned affix as DamagePipelineEffect |
| 1600 | `LIFESTEAL` | LifestealStage | heal attacker `dmg×lifesteal/100` |
| 1700 | `FEROCITY` | FerocityStage | each 100 ferocity queues a SECONDARY strike |
| 1900 | `INDICATOR` | (Damage)IndicatorStage | hook point for damage-number display |
| 2000 | `APPLY` | ApplyStage | writes `finalDamage` back into the Bukkit event |

The remaining reserved-but-empty **content/affix** slots (400, 700, 1400, 1500) are filled by later WPs
and must be filled with `DamagePipelineEffect`s registered through `CombatModule`, never new hardcoded
stages — that rule governs gameplay/affix content (Shielded, Thorns, ability mods, effect offense).
**Pipeline *mechanism* stages are the exception:** foundational infrastructure like `WeaponBaseStage`,
`ArmorMitigationStage`, and (WP-2.3a) `ElementalBreakdownStage`/`ResistancesStage` are compiled
`DamageStage` classes by design — they carry no balance numbers of their own (the resistance curve
reuses the shared `x/(x+100)` form and reads `resistance_<type>` *stats*, which are the data), so they
are not the "hardcoded content" the rule forbids.

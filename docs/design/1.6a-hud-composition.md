# 1.6a — HUD composition order and slot budget

Presentation moves off hand-spawned entities onto RamCore's display API, and the composable HUD
pieces are pure functions so they unit-test.

## Action bar (`composeActionBar`)

One line, **3 segments in fixed order**, updated every 5 ticks per online player:

`❤ hp/maxHp   ❈ def   ✎ mana/maxMana`  (red / green / aqua)

**Slot budget: 3 segments.** Later HUD additions share this line and must respect the budget:
- WP-4.1c (buff UI) appends a buff summary; it must fit without pushing HP/DEF/Mana off-screen —
  prefer a compact `+N buffs` or icon row over per-buff text.
- Cooldowns (WP-1.3 exposes `AbilityService.remaining`) may show the shortest active cooldown here;
  keep it to one trailing segment.

## Boss bar

Shows the player's **active skill**: `<Skill> Lv N  xp/needed`, colour = the skill's bar colour,
progress = xp / xpToReach(level). Set on XP gain and on kill (combat); restored from
`lastActiveSkillId` on join. Adventure `BossBar`, hidden on quit.

## Damage indicators (`RpgPresentation.damageIndicator`)

A short-lived center-billboarded `TextDisplay` at the victim, spawned through
`DisplaySpawner.spawn` (region-safe) — no more manual `world.spawn` + `Transformation`. Text/colour
come from the pure `RpgPresentation.damageIndicatorText` (crit = yellow, true = white, else red;
nothing below 0.5 damage; rounded to a whole number). The returned `DisplayHandle` is bound and closed
after ~16 ticks on the location's context, so it never leaks. The dead placeholder `IndicatorStage`
was removed. **Cap concern:** each hit spawns one display; heavy AoE could spawn many — a future cap
should live here if it becomes a problem (bosses in 6.4).

Lang: none — the HUD is glyphs + numbers, no translatable words.

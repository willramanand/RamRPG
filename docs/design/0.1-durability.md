# 0.1 — Durability (decision D2 = YES)

**Decision D2: RPG items carry durability.** Durability is a first-class RPG stat on an item instance,
not vanilla `Damageable`.

Rules the implementing WPs (2.1b schema, 2.1c inert path, 2.2 behaviour, 3.3b repair) must honour:

- **Inert at 0, never breaks.** At `durability == 0` the item goes inert via the single `InertReason`
  path (`InertReason.ZERO_DURABILITY`, WP-2.1c) — it contributes no stats, enchants, reforge, sockets
  or set membership — but the `ItemStack` is never destroyed. The vanilla `PlayerItemDamageEvent` is
  cancelled for RPG items so Minecraft never breaks them; non-RPG items keep vanilla behaviour.
- **Drains on use.** WP-2.2 drains durability through a `DamagePipelineEffect` at `APPLY` (2000) and on
  the relevant use events; drain rates are documented in `docs/design/2.2-*.md`.
- **Repaired at the smithing station.** WP-3.3b adds a repair recipe (the durability sink). Repair
  restores durability only — it must not reset quality, upgrade level, sockets or enchants.
- **Schema.** `durability` and `maxDurability` land in the single Phase-2 instance schema bump
  (`ItemInstanceData`, `ItemSchema.CURRENT = 2`) owned by **WP-2.1b**; V1→V2 defaults durability to max.

There is no durability code today; this file records the decision so 2.1b/2.1c/2.2/3.3b implement one
consistent model rather than diverging.

# 1.1a — Loot tables and drop rates

Mob drops move from RamRPG's inline `EntityProfile.loot/lootPool/lootRolls` onto RamCore's
`loot.LootTable`, resolved by `LootGenerator` on death (`LootListener`). `RpgLootTables` builds the
tables; `RpgLootFunctions` stamps each drop with a roll seed.

## Model

- **Independent-chance drop** (each item rolls its own chance; any number can drop): one single-entry
  `LootPool` per item, `rolls = 1`, gated by `LootConditions.chance(c)`. Chance `1.0` = guaranteed
  (no condition).
- **Weighted pool** (pick N by weight): one `LootPool` with all entries and `rolls = N`.
- Every entry's reward is `LootReward.of("ramrpg:item", RpgItemPayload(item, ItemInstanceInit), count)`,
  and `RpgLootFunctions.SEED` stamps `rollSeed = random.nextLong()` on generation so a dropped item's
  stat rolls are reproducible from the stored seed (this closes the old seedless drop path).
- `LootListener` turns each `RpgItemPayload` reward into an `ItemStack` via `ItemInstanceService.create`
  on the entity's region context. Building the stack is the only server-coupled step and lives here.

## Deviation from the plan (recorded)

The plan specified `EntityProfile.lootTable: ContentId?` (a reference into a loot-table registry). This
WP holds `lootTable: LootTable?` **directly** on the profile instead — the reference model plus a
loot-table content registry lands with the content loader (**WP-1.5a**), which owns loot content. This
keeps 1.1a from needing a new registry wired through `RamRPG.kt`. The Phase-1 rule-7 waiver covers the
breaking removal of the old loot fields and the RPG `LootEntry` type.

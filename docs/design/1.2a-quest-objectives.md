# 1.2a — Quest model and objective mapping

Quests are now thin wrappers over RamCore's objective system. `QuestDefinition` keeps its authoring
surface (`goal`, `rewards`, `daily`, `category`) and exposes `objective(): ObjectiveDefinition`;
`QuestService` delegates all progress tracking to a RamCore `ObjectiveTracker`. RamRPG no longer
stores quest progress on the player profile — `PlayerRpgData.questProgress`/`questCompleted` are gone.

## Goal → ObjectiveTask mapping

Targets are lowercase (`[a-z0-9_.:-]` or `*`); a `*` target matches any event of that action.

| QuestGoal | ObjectiveAction | task id | target |
| --- | --- | --- | --- |
| `KillEntityProfile(profileId, n)` | `KILL` | `kill` | profile id (`*` = any mob) |
| `BreakBlocks(material, n)` | `INTERACT_BLOCK` | `break` | `material.name.lowercase()` |
| `GainSkillXp(skill, n)` | `RUN_ACTION` | `xp` | skill id (`ramrpg:combat`) |

`required` = the goal's target count. `QuestProgressListener` turns Bukkit events into
`ObjectiveEvent`s (kill → amount 1, block break → amount 1, skill xp → amount = xp gained), and
`QuestService.fire` applies them; a reward fires on the single `ObjectiveUpdate` whose
`objectiveCompleted()` is true (so each quest rewards exactly once).

## Persistence

Progress lives in an `ObjectiveProgressStore` backed by `Stores.file(dataFolder/quests, …)` — persisted
across relog and restart, restored by `tracker.load()` at startup. `registerObjectives()` registers
every quest's objective after the registry is populated. Daily quests reset via
`tracker.reset(subject, objectiveId)` on day rollover; only `PlayerRpgData.lastDailyReset` remains on
the profile.

## Deviations (recorded)

- **No migration.** The plan's `QuestProgressMigrationTest` and the dataVersion-v2 migration are
  skipped: RamRPG is in-house on fresh servers, so there is no stored quest progress to migrate. The
  fields were simply removed. See the [dataVersion ledger](F5-dataversion-ledger.md).
- `QuestDefinition` keeps `goal: QuestGoal` (author-friendly) with a derived `objective()`, rather
  than taking a raw `ObjectiveDefinition`; and rewards stay `List<QuestReward>` — WP-1.2b re-models
  rewards onto RamCore's `RewardPlan`.
- `QuestChainOrderTest` (for chained multi-task objectives) is replaced by `QuestProgressTest`, since
  RPG quests are single-task; it asserts progress advances and completes exactly once at the target.

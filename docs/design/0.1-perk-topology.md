# 0.1 — Perk topology (decision D3)

**Decision D3: one perk tree per combat-ish skill (combat, sorcery, agility) plus one general tree —
four trees total.** No separate class system. WP-5.2 (archetypes) stays **deferred** and is raised only
if WP-5.1c's review concludes the four trees do not produce visibly distinct builds.

Trees (skill keys exist today in `RamSkills`):

| Tree | Source of points | Theme |
| --- | --- | --- |
| `combat` | Combat skill levels | melee damage, crit, ferocity, lifesteal |
| `sorcery` | Sorcery skill levels | ability power, mana, cooldowns, elemental |
| `agility` | Agility skill levels | speed, evasion, attack speed, mobility |
| `general` | all skills / shared budget | health, defense, fortune, wisdom, utility |

Model the implementing WPs (5.1a API, 5.1b GUI, 5.1c content) must honour:

- `PerkTree(key, displayName, nodes)`; `PerkNode(key, cost, prerequisites: AllOf|AnyOf, maxRank,
  effectsPerRank, gridPosition)`.
- Node effects flow through `Effect` only (`StatEffect` / `TriggeredEffect` / `AbilityUnlockEffect`) —
  no bespoke perk hooks. `AbilityUnlockEffect(AbilityKey)` is the first `Effect` that grants a
  capability rather than a number.
- Persistence: `perkRanks` and `perkPointsSpent` on `PlayerRpgData`, **dataVersion v4**, owned by
  WP-5.1a (see [F5 ledger](F5-dataversion-ledger.md)); absent ranks default to empty, never null.
- `gridPosition` validated at load (no overlaps, inside menu bounds) or the GUI silently drops nodes.
- Point curve per skill level and respec cost are chosen in `docs/design/5.1a-*.md`; respec placeholder
  is 10% of lifetime skill-XP value (see [economy placeholders](0.1-economy-placeholders.md)).

No perk code exists today; this records the topology so 5.1a does not invent a class system.
